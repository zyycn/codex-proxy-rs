## 判断与范围

现有方向正确，适合当前系统。SDK、Runtime、Core、Admin、Store、Host 的分工，以及冻结执行计划、类型化中间件和按实例隔离故障的设计，应继续保留。需要整理的是宿主内部合同和所有权表达，不是推倒重建插件框架

“通用”指插件能组合网关已有能力，挂接明确的执行位置；当前系统不需要发展成任意 Provider 平台、不可信代码市场或通用工作流引擎。“优雅”以新增或调整一项能力时是否只触及所属合同、适配器和业务 owner 判断，不以文件少、抽象层多或对错误插件宽容为标准

本次包含宿主 SDK、Runtime、Core/Admin 接入、Store 插件存储、Host 进程监督、管理 API、插件管理页面及宿主注入的页面桥。独立插件只作为公开合同的消费者和验证参考，其业务处理器、业务恢复和页面业务不属于整理范围

### 宿主与插件各自负责什么

| 场景 | 宿主责任 | 插件责任 |
| --- | --- | --- |
| 输入输出 | 安全解码、调用关联、公开合同、原生服务输入约束 | 业务字段含义、结果正确性、业务数据完整性 |
| 失败 | 按调用、会话、实例边界拒绝、隔离、释放资源 | 决定业务重试、恢复、幂等与检查点 |
| 状态迁移 | 排空、隔离暂存、CAS、事务提交及自身失败恢复 | 声明 schema、提供迁移算法、解释私有数据 |
| 原生能力 | 提供可独立使用的服务，沿用身份、账本、审计与事务 | 选择资源、组合调用、安排跨资源业务流程 |
| 兼容性 | 准确声明合同和弃用窗口，清晰报告不兼容 | 适配所依赖的合同和宿主版本 |

不加入猜测插件意图、补造字段、修正业务结果、隐藏失败、自动重放副作用或按插件身份设置的兼容特例。公开默认值、显式失败策略、进程监督、事务恢复和资源回收仍保留，它们保护宿主自己的合同

本次不新增插件专用账本、业务状态表、补偿任务平台、动态依赖注入框架或权限清单系统，也不为尚未出现的能力预留多层抽象。完整信任仍是现有信任模型，进程隔离不表述成安全沙箱

### 需要修正的合同漂移

- [能力文档的重试策略](../../backend/crates/gateway-plugin/sdk/docs/capabilities.md#重试决策)写整条链最多等待 2 秒；[SDK 并发与期限](../../backend/crates/gateway-plugin/sdk/README.md#并发与期限)允许显式声明预算，[Runtime 实现](../../backend/crates/gateway-plugin/runtime/src/adapter/policy/retry.rs)按匹配实例的声明预算及请求剩余期限计算整链预算，不能把默认值写成硬上限
- [API 发布状态](../api.md#发布状态)把 `running` 解释为启用且发布版本一致；实际实例列表从 `runtime.status == Running` 派生 `running`，运行诊断缺失时又退回发布事实判断，需要统一字段说明及缺失诊断的表达
- 实例配置拒绝未接受制品时仍提示“接受该版本声明的权限”，与完整信任模型不一致；清理这类历史措辞，不能据此恢复权限清单设计

上述是可定位的合同或表达问题。RPC 和控制面拆分属于设计整理，大正文吞吐属于需要测量的风险，不能混写成已证实的严重运行故障

独立示例当前固定的 SDK/CLI 提交为 `5afea450baa963f2e14ec73893a0827b5c9d85d7`，其说明标注 RPC v5；当前宿主兼容清单为 RPC v7。该组合不能直接充当当前宿主的兼容验收证据，也不构成本次给宿主增加旧协议补丁的理由

## 目标结构

| 模块 | 唯一负责的事实或资源 | 接入原则 |
| --- | --- | --- |
| SDK | 作者公开类型、协议编码、类型化调用及会话辅助 | 不依赖宿主 workspace 业务 crate，不包含插件业务恢复 |
| Core | 身份、原生执行计划、路由资格、准入、租约、重试安全、结算 | 插件返回决定或事实，Core 保留最终业务裁决 |
| Admin | 安装、配置、切换、迁移和管理操作编排 | 使用 Store 事务及 Runtime 准备端口，不直接控制子进程 |
| Store | 制品、配置、私有状态及审计的持久化一致性 | 不持有运行状态，不解释插件业务数据 |
| Runtime | 插件实例、协议会话、能力适配、调用资源及状态投影 | 通过所属业务端口调用原生能力，不复制原生规则 |
| Host | 进程与网络 I/O 的生命周期 | 不解释插件清单、能力和业务结果 |
| API 与管理端 | HTTP 合同、管理操作、展示及页面桥 | 消费后端事实，固定页面目标，不产生第二套运行判定 |

```mermaid
flowchart LR
  A[Admin 配置操作] --> B[Runtime 准备候选]
  B --> C[Store 原子提交]
  C --> D[Core 发布不可变快照]
  D --> E[请求持有执行计划]
  E --> F[Runtime 能力适配器]
  F --> G[RPC 会话与调用资源]
  G --> H[插件进程]
  H --> I[Runtime 宿主回调]
  I --> J[Core / Admin 原生服务]
  G --> K[Host 进程与网络监督]
```

图中的箭头表示运行协作，不表示 crate 可反向依赖；Core/Admin 定义端口，Runtime 实现或消费端口，组合根注入具体实现

状态与资源沿已有所有权释放：发布快照持有准备集合，集合共享准备实例，实例持有会话，调用持有容量与回调资源，响应流持有仍需存活的调用引用。诊断是这些 owner 的只读投影，不能反过来驱动其生命周期

## 整理清单

以下各项共同构成一次交付，允许按依赖顺序实现和提交，但全部验收后才算整理完成

### 公开合同与原生能力接入

- 整理能力、挂载点、RPC 方法、默认预算、错误边界和弃用声明的权威来源，修正上述文档漂移；清单、CLI、握手、运行适配和兼容清单使用同一合同含义
- 对已经在 SDK 声明的方法名复用常量，Runtime 保留唯一明确的回调分派入口，消除散落的同义字符串和交叠的分派规则；不为此引入动态注册框架
- 延续 [公开服务注册表](../../backend/crates/gateway-admin/src/public_service/registry.rs)和 settings/accounts 现有合同生成测试，原生服务操作仍由所属服务声明；只收敛本次实际涉及的重复定义，不建设全量 IDL 平台
- SDK wire 类型与宿主领域类型可以保持各自边界，但转换必须集中、可追踪，并覆盖默认值、未知字段、错误及二进制载荷；不能为消除类型转换而让 SDK 依赖 Core/Admin
- 保留当前身份查询与模型执行的独立端口，避免查询能力再次要求执行端口就绪；管理操作、基础数据读取和模型执行也不混成一个万能服务
- 协议默认值和安全解码属于宿主合同；插件业务结果仅做宿主消费所必需的检查，不加入业务纠错、额外未知字段拒绝或自动补齐
- 沿现有适配、回调、结果转换及其测试核对默认填充、重试和恢复分支；发现没有宿主不变量或公开合同依据的插件业务补偿时删除，不因名称看起来通用就保留，也不把原生业务规则误删为插件兜底

交付结果：新增一项同类宿主能力有明确的合同、业务 owner、适配位置和合同测试，其他层只消费结果

### RPC 与回调资源所有权

- 将 `rpc/session.rs` 中调用状态转换、挂起恢复和终结操作按职责内聚，保留 `admission`、`dispatch` 已有边界；`RpcSession` 负责对外调用及会话协调
- RPC 调用表继续作为协议调用状态的唯一权威，容量 permit、执行 permit、resume 任务和结果交付不能各自维护另一套结束标志；已有回调资源索引只管理其实际资源，不复制协议状态机
- 统一成功、失败、取消、超时及进程退出的终结路径，保证释放、回调撤销和副作用封存发生在对 Core 通知完成之前；锁内完成状态变更，锁外销毁已移出的调用资源并通知结果；已发送调用取消时，在锁内同步撤销调用权利，避免取消确认越过副作用封存，回调 finish 保持幂等且非阻塞
- 保留 `Running / Suspended / Resuming` 的明确转换和 epoch 校验，`next` 等待的预算暂停不能扩展为任意回调免费等待，资源流接管寿命也不能提前释放调用容量
- 将 `callback/mod.rs` 的端口组装、作用域登记和方法分派拆成相邻私有模块，沿用 [CallResources](../../backend/crates/gateway-plugin/runtime/src/callback/call_resources.rs)和 [CallbackScope](../../backend/crates/gateway-plugin/runtime/src/callback/scope.rs)，不新增全局服务定位器
- 六类 middleware 共用一次性 `next` 与必要的资源机制，HTTP 正文、WebSocket 消息、模型事件和服务结果继续保留各自类型与终态语义

交付结果：每项异步资源都能从创建点追到唯一终结责任；取消、迟到回复和实例换代不依赖多个模块互相修补状态

### 控制面、发布与私有状态

- 从 `use_case/plugins/instances.rs` 分离实例查询投影、配置输入检查及状态迁移编排；普通保存、版本切换、回滚继续汇入已有配置提交路径，不复制三个用例
- 保留“候选准备 → CAS 事务提交 → 激活与发布”的顺序，准备失败不污染持久配置，提交后失败不得伪装成事务未发生，也不得恢复旧配置覆盖已提交事实
- 保留迁移排空、暂存、校验和原子提升，以及单一迁移失败恢复出口；恢复只恢复宿主自身配置与暂存状态，不尝试理解或修复插件业务数据
- 紧急停用继续绕过损坏插件的准备流程；删除、停用、换版和回滚各自使用现有数据保留语义，不借整理删除历史配置或私有数据
- 兼容状态缓存仍以固定宿主及制品摘要为键，仅缓存确定结果；缩短 `package_status` 的全局缓存锁范围，不持锁等待包加载和检查。允许无副作用的重复检查，不另建复杂缓存协调服务
- `PreparedSet`、`PreparedInstance` 与弱索引继续承担现有发布和复用职责；实例崩溃不得使其他实例和原生网关的整套配置失效

交付结果：管理员的一次变更只有一条可追踪的提交与发布路径，插件状态迁移不会变成宿主业务工作流引擎

### 运行状态与最小诊断

- 明确三类不同事实：期望启用、已发布配置、实例运行状态；API 字段说明、Runtime 投影和页面文案保持一致
- `runtime.status` 作为运行状态的权威，`running` 只作为它的派生兼容字段；保留已发布 revision 的独立含义，不拿“已发布”证明进程或插件业务健康
- 诊断缺失时不制造失败原因，也不推断运行正常；停用仍可由配置确定，已启用且运行事实缺失时明确表达未知状态，并同步 API 类型、前端显示及测试
- 从现有调用表、准入资源和回调资源投影在途调用、执行、等待、恢复等待、驻留回调和活动流的必要计数；状态采样不增加新的可写运行状态表
- 沿现有 tracing 补充排队、执行和终结原因，使用安全的关联标识；不记录正文、凭据和原始 stderr，不为实例 ID 建立无界指标标签
- 在现有插件详情中提供必要诊断，列表继续简洁；故障信息回答当前失败位置和可执行操作，不推断插件业务该如何修复

交付结果：管理员和开发者能区分未发布、准备失败、运行失败和资源拥塞，诊断不会成为第二套状态机

### 页面桥与管理端

- 从 `usePluginFrameSession` 分离模型流的创建、pull、终结及计时，页面会话保留目标、iframe、资源 URL、主题和整体销毁责任；注入桥按对应的消息与流职责整理
- 在 `management/bridge-contract.ts` 集中共享消息合同和常量，提供与实际注入 API 一致的公开类型；不让插件复制宿主内部实现，也不强制插件安装宿主运行时依赖
- 固定 `{instanceId, artifactSha256, revision}`，保留来源窗口、origin、channel、session 检查；换页、停用、换版及身份变化都由所属会话取消在途资源
- 普通管理响应保持原始字节，模型桥保持标准 `Response` 和按需读取，不重建插件业务响应、不自动重放过期请求
- 管理列表、详情和导航沿用后端状态与已有目录 Store，复用项目请求取消机制及基础组件，不为本次整理重排页面或创建另一套插件管理状态

交付结果：宿主页面桥的合同和资源寿命独立可验证，插件页面业务不进入宿主管理端

### 容量、验证与文档收口

- 本次完成普通小请求、大正文、慢读流和并发回调的对照测量，记录宿主及子进程 RSS、吞吐、P95/P99、取消完成时间和恢复后的资源占用
- 测量覆盖当前默认准入容量的正常区间、接近饱和及超过容量的情况，并混合大帧与小控制消息；输入规模和运行环境随结果保存，不能仅以空载微基准判断
- 大正文如无实际瓶颈，保留现有传输并记录依据；若出现不可接受的额外缓冲或阻塞，在本次内针对具体 owner 修复并复测，不把测量或修复推给“下一阶段”
- 优先处理重复序列化、无必要副本和无界积压；不得随意加入一个低于宿主原生正文合同的固定总量上限，也不先验引入共享内存、第二传输通道或全面流式协议改造
- 合同与故障用例优先复用 Runtime 现有测试 worker、真实子进程测试及原生服务 fixture；独立示例不兼容时使用匹配当前 SDK 的宿主测试 fixture，不修改宿主迁就示例
- 已承诺的公开兼容和弃用窗口继续履行；内部整理默认保持协议版本，确需破坏 wire 合同时必须显式更新版本及兼容声明，不能暗改合同
- 实现完成后把有效合同写回架构、API、SDK 和插件使用文档；部署行为未变，不制造部署文档改动，任务经过与测试报告保留在任务报告中；删除被替代的内部路径和死代码

交付结果：性能风险得到有数据的结论，测试和文档与最终实现一致，没有遗留双路径或待后补的关键合同
