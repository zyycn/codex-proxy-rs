# 账号错误保护改造计划

状态：已完成实现与本地验收，真实上游及实际部署环境尚未验证

目标：把现有过载保护改造成由用户规则驱动的账号错误保护，匹配、计数、冻结和恢复机制不依赖预设错误场景

关联需求：[#536](https://github.com/zyycn/codex-proxy-rs/issues/536)

代码核对基线：`main@a6031310f`

本文供实施和验收使用，描述目标合同与改造步骤；当前产品行为仍以 [API](../api.md#账号错误保护) 和 [架构](../architecture.md#worker-与账号冻结) 为准

## 1. 范围与设计原则

- 管理员配置匹配条件，系统不内置哪些错误“值得冻结”的判断，不根据错误码推断账号、网络或内容问题
- 保护对象是账号，动作是暂停后续调度；继续复用冷却、到期恢复、可选探测与手动解除能力
- 首期提供一个全局策略、多个匹配规则，共用阈值、计数有效期和冷却配置，不引入规则优先级、每条规则独立动作或通用脚本引擎
- 原始错误透传、Provider 协议分类、认证与额度处置、重试及续接合同继续由现有 owner 负责，规则命中不改变这些语义
- 新安装与旧过载保护升级均默认关闭且规则为空，空规则集合不匹配任何错误；启用时必须至少有一条有效规则
- 冻结只表示管理员定义的调度保护，不证明账号失效或错误根因已经确认

首期覆盖内置 OpenAI / xAI 普通模型执行链中已有账号归属的上游失败，HTTP 拒绝和 SSE / WS 流内失败使用同一匹配合同。受管上游适配器按已有结构化失败合同接入，缺失事实保持缺失，不解析插件私有正文补齐

客户端取消、本地超时、连接失败、请求校验、调度失败、插件 RPC 故障和后台管理操作不属于这套上游响应匹配输入。探测、预热等内部调用不参与计数。覆盖边界按失败来源和调用用途定义，不按某几个错误码排除

本次不包含自动切换出口或指纹、自动继续对话、修改请求内容、跨账号迁移续接，以及不具备现有 attempt 生命周期的独立协议链路

## 3. 配置与匹配合同

### 策略结构

建议在运行设置中以 `accountErrorProtection` 组合保护配置，复用 `GET /api/admin/settings` 与带 `configRevision` 的设置更新接口，不另建规则管理服务

| 配置 | 目标语义 |
| --- | --- |
| `enabled` | 总开关，新安装默认关闭 |
| `rules` | 用户规则集合，新安装为空 |
| `threshold` | 同一账号累计匹配失败的触发阈值，沿用 2～1,000，默认 12 |
| `windowSeconds` | 距离最后一次匹配失败的计数有效期，沿用 60～3,600 秒，默认 600 |
| `durationSeconds` | 触发或探测失败后等待的冷却时长，沿用 300～604,800 秒，默认 7,200 |
| `probeEnabled` | 到期后是否要求探测成功才解除保护，保留现有开关语义 |
| `probeModel` | 探测模型，可空，复用已有模型选择能力 |

每条规则有稳定 ID、可编辑名称和一组条件，ID 用于展示命中原因，不建立每条规则独立的计数器。规则内条件为 AND，规则之间为 OR；条件中的多个候选值为 OR

规则集合和单条规则均禁止隐式“匹配所有错误”。每条规则至少包含状态码、错误码、错误类型或错误信息中的一个条件，只有 Provider 范围不构成有效规则。禁用策略可以保存空集合，非空集合中的每条规则仍必须通过校验

### 字段与运算

| 字段 | 数据来源 | 运算 |
| --- | --- | --- |
| Provider | 本次执行选中的 Provider 标识 | 等于任一候选值，可不限制 |
| 状态码 | 上游失败实际携带的状态码 | 等于任一候选值 |
| 错误码 | 上游结构化 `code` | 等于任一候选值 |
| 错误类型 | 上游结构化 `type` | 等于任一候选值 |
| 错误信息 | 上游结构化 `message` | 等于或包含任一候选文本 |

- 用户可以只匹配一个字段，也可以组合字段；不预设错误码选项，不以已知错误枚举限制输入
- 文本比较支持显式的忽略 ASCII 大小写选项，默认关闭；等值比较去除两端空白，比较处理不改写原始响应
- “字段缺失”使用显式候选值表示，与空字符串不同；普通文本条件遇到缺失字段不匹配，不把缺失视为通配符
- 包含匹配禁止空白候选文本，避免空字符串隐式命中所有消息；空字符串等值比较与字段缺失分别表达
- 首期不加入正则、任意 JSONPath、脚本和全文响应扫描；规则只消费约定字段
- message contains 只检查 UTF-8 安全截断的前 8 KiB，equals 比较完整字段，超长字段不视为缺失
- 最多 32 条规则、每规则 8 个条件、每条件 16 个候选值；id/name 最多 128 字符，message 候选最多 1,024 字符，其余候选最多 256 字符，全部规则文本与探测模型的 UTF-8 总量最多 64 KiB
- Admin 使用 Core 的同一校验与编译规则，非法配置整次保存失败，不忽略坏规则后继续启用

普通编辑以“状态码 / 错误码 / 错误类型 / 错误信息”呈现，不要求用户理解内部表达式。多值、大小写和字段缺失属于就近展开的条件选项，所有规则都必须能完整展示、修改和删除

### 输入事实

HTTP 请求被拒绝时使用原始上游状态码与已解析字段，禁止使用网关最终向客户端返回的投影状态码

HTTP 200 后的 SSE 失败或 WS 流内失败优先使用失败事件明确携带的状态码，没有则为空。握手成功的 200 / 101 不作为流内错误的状态码，也不能根据错误码补造 400 或 503

保护匹配读取 Provider 已解析的错误事实，不从诊断文案、完整 JSON、HTML 页面、日志或请求正文中二次搜索。已有解析无法提供字段时保持为空，状态码仍可单独匹配

示例仅说明组合语义，不作为默认配置：一条规则要求“状态码等于 400 且错误码等于用户指定值”，另一条规则仅匹配用户指定错误码，从而覆盖没有独立状态码的流内失败

## 4. 职责与调用链

目标链路：

```text
运行设置提交并发布策略
  → 请求冻结策略快照
  → Provider 解析本次上游失败
  → attempt 边界提交账号归属与结构化失败事实
  → Core 匹配规则并决定是否记录保护反馈
  → Store 原子累计并按阈值建立冻结
  → 调度消费账号冷却事实
  → Admin worker 探测、解除或顺延冻结
```

| owner | 责任 |
| --- | --- |
| Core `account` / `settings` | 中立保护策略、匹配值对象、账号保护状态及端口；不解释 OpenAI 或 xAI 正文 |
| Core `engine` | 冻结请求策略、识别普通执行与内部调用、每 attempt 一次反馈、遵守发送和交付边界 |
| Provider | 解析原始上游字段，提供实际账号及凭据代次；继续拥有认证、额度与协议分类 |
| Admin | 设置校验入口、恢复编排、手动解除和管理审计 |
| Store | 设置事务、revision、Redis 计数与冻结的原子实现；不内置错误匹配名单 |
| API / 前端 | wire、表单、校验提示与状态投影，不重新解释错误文本或实现另一套运行匹配器 |

`ProviderCallMetadata` 继续描述执行元数据；保护上下文在取得真实账号时单独绑定该账号及凭据 revision，不按账号 ID 回查“最新 revision”替代本次执行的版本

接入位置须覆盖初始 HTTP 拒绝、流内错误、被重试丢弃的失败与最终失败，不能只在最终错误持久化处计数。取消、超时、Drop 和原始失败事件的后续交付不能重复触发保护副作用

受管适配器仅消费 [SDK `UpstreamFailure` 合同](../../backend/crates/gateway-plugin/sdk/docs/upstream-adapters.md#事件结算和续接) 已提供且有账号归属的事实；RPC 与插件故障保持原有隔离边界。若公共合同确有缺失，先列出字段缺口，不在 Runtime 中猜测插件业务含义

保护参数随已有请求快照传递，取代热路径的容量策略专用缓存。规则修改产生独立的保护策略代次，只在保护相关配置改变时更新；无关设置变更不重置计数。新请求使用新策略，已经开始的请求继续持有原快照

## 5. 计数、冻结与恢复

### 计数

- 以账号、凭据 revision、保护策略代次隔离证据，同一策略下任意规则命中都累计到该账号的同一个计数器
- 一个实际 attempt 最多增加一次，规则重叠不重复计算；真实执行的重试属于新 attempt，沿用现有按尝试计数的口径
- 每次匹配失败续期计数 TTL，未命中的失败不续期、不清零；完整成功的普通调用清除相同代次下尚未形成冻结的证据
- 部分输出、客户端断开、本地取消和探测成功不当作普通成功清零；迟到成功不能清除新策略、较新证据或已有冻结
- 并发递增、阈值判断与冻结建立必须保持原子性，不通过读取计数后在调用方无条件写冻结
- 多个在途失败越过阈值只建立一代冻结；处于冻结期间的迟到普通失败不反复刷新冷却终点或创建新一代

每次反馈携带执行取得的保护状态代次。手动解除、规则更新或凭据变更后，旧反馈不得重新冻结账号；状态转换在 Store 端以代次比较完成，不依赖进程内标志

### 冻结与调度

冻结保存账号与凭据 revision、保护策略代次、冻结代次、到期时间、是否需要探测，以及用于管理展示的有界规则标识和名称快照

规则匹配阶段可以读取错误信息，但保护状态和普通日志不复制完整上游 message、响应正文或请求内容。诊断关联复用现有 request / attempt 体系，详细错误继续受现有访问边界控制

沿用账号 `rate_limited` 投影，以中立原因区分“错误保护”和上游限流，不新增 PostgreSQL 账号错误状态。冻结原因不使用 `invalid_prompt_freeze` 等场景枚举

上游限流、账号错误保护与模型级冷却分别保有恢复条件，解除一种原因不得抹掉另一种仍有效的原因。复用现有冷却存储与聚合出口，按需要扩展独立原因事实，禁止以单个 `kind` 覆盖造成恢复信息丢失

保护生效后阻止新的账号准入，已持有有效执行租约的请求允许完成。等待中的请求在取得执行资格前复核保护状态；固定账号和精确续接继续遵守原调度及续接合同，不因规则命中擅自换号

触发保护不新增重试资格。某条原本可重试的请求因账号冻结而无法继续使用该账号时，仍由现有 Core 策略决定换号、结束或要求客户端恢复

### 恢复与配置变更

- 无探测：冷却到期解除错误保护
- 有探测：到期后仍阻止普通调度，worker 复用连接测试进行真实调用；成功解除，失败按该冻结的冷却时长顺延
- 冻结持有必要恢复参数快照，后续调整阈值、时长或规则不改写已存在冻结的恢复参数
- 关闭保护或关闭探测时，已有冻结等待原冷却截止后解除；全局关闭不被旧请求快照反向撤销
- 修改规则后，新计数从新策略代次开始，已存在冻结继续按上述恢复合同处理；旧请求不能在新策略发布后建立或延长保护
- 手动恢复复用现有账号恢复入口，清除保护、计数及其他本地错误、额度和冷却状态，并推进状态代次；旧探测结果和旧在途失败均不能覆盖管理员操作
- 探测结果必须同时匹配账号凭据、策略归属与冻结代次；账号删除、禁用、凭据轮换和 worker 重启沿现有生命周期收敛
- 自动到期或探测只解除保护，凭据、额度、启停及其他冷却仍独立判断

探测成功只证明本次模型调用成功，不证明原始失败请求已经可用。探测失败不进入普通保护计数，也不触发本功能之外的恢复动作

### 失败与资源约束

规则在保存及快照发布时校验、编译，热路径只做有界匹配。存储反馈失败或超时保留原始客户端结果，记录安全诊断，不把保护组件失败替换成模型请求失败；存储不可用期间不承诺保护触发成功

反馈需要有界等待，不能无限阻塞流终结、取消或租约释放，也不启动无主后台写入。Redis 时间用于计数到期和冻结时间比较，状态更新具备代次校验和幂等边界

计数与冷却仍是可重建协调状态。Redis 状态丢失不改变持久账号事实，也不从历史错误记录自动重放冻结

## 6. 解除场景耦合与迁移

### 自适应并发下调

实施取舍：通用错误保护只执行账号冷却，移除该卡片的自适应并发下调选项及恢复 worker 中相应自动写入，不将其迁移为任意错误都可触发的动作

这是一项明确的行为变化：旧配置开启自动下调的部署，升级后停止这项自动调整；已经持久保存的账号并发上限保持原值，管理员可以手动修改。若仍需自动并发控制，应另行定义基于负载证据的能力，不把容量场景判断留在通用保护内部

实施时清理保护专用的并发峰值采样、读取端口、设置字段、表单和测试；共享的并发管理能力及其他真实调用者继续保留

### 配置、状态与公开合同

1. 新增编号数据库迁移，遵守[迁移冻结规则](../../backend/migrations/README.md#冻结规则)，不修改已冻结的迁移
2. 新安装和升级部署均使用关闭、规则为空的默认策略，阈值、计数有效期、冷却及探测参数不继承旧值
3. 删除全部旧保护设置列和相关转换逻辑，不生成容量规则，管理员按需重新配置并启用
4. `is_capacity_error` 在协议分类中仍有职责，不因清理保护配置机械删除
5. 原有 Redis 冻结在升级后保留截止时间、探测要求和代次边界；转换须幂等，不提前解冻、不重复计数、不每次启动重新延长冷却
6. 未形成冻结的容量计数和峰值属于旧策略证据，允许在切换时清除并从新代次开始；不得连带清理上游限流和模型冷却
7. 运行设置、备份导入导出、管理 API 以及[生成的 SDK 设置合同](../../backend/crates/gateway-plugin/sdk/README.md#生成服务合同)同步处理，业务配置保留唯一权威来源
8. 备份继续使用完整 PostgreSQL dump，旧备份按既有停机恢复流程恢复，再执行编号迁移；恢复必须使用空 Redis。管理端写入切换为 `accountErrorProtection`，旧字段及新旧混合请求都拒绝，避免旧客户端静默覆盖新规则
