# 工程规范

## 先确定任务合同

| 用户要求 | 默认交付 |
| --- | --- |
| 解释、审计、诊断 | 查明证据和边界，只报告结论，不擅自修改 |
| 修复、实现、重构 | 在已证明的 owner 内修改，并按风险验证 |
| 文档、计划 | 只更新被授权的文档/计划，不顺手实现功能 |
| 生产排障 | 先核对实际 revision、配置、数据和日志；写操作需要明确授权 |

最新的用户范围修正优先。不要用“顺便优化”扩大 mutation、部署、数据清理或外部操作范围。

## 事实优先级

1. 当前可复现输入与运行结果。
2. 当前部署 revision、配置、数据库和日志。
3. 当前源码、测试与公开合同。
4. 架构和项目文档。
5. 记忆、历史提交和参考项目。

低优先级来源只能帮助定位，不能覆盖当前事实。观察到相关性时标为线索；只有调用链、状态变化或可复现
实验闭合后才称为根因。

## 工作流

1. 检查工作树和运行环境，区分用户改动与本任务范围。
2. 找到入口，沿调用链追踪状态的创建、持久化、读取、转换和输出。
3. 标出协议、领域、存储、异步任务和外部依赖之间的 owner。
4. 用最小证据证明断点；如果现象已经由环境/数据解释，不先写代码。
5. 在 owner 内做最小完整修复；行为变化通过公开接口或外置集成测试固定。
6. 同步受影响的 API、架构、部署、迁移或 skill 文档。
7. 运行与风险相称的格式、lint、测试和静态检查，再复核最终 diff。

简单文案和机械修改直接完成，不套审计模板；高风险或不可逆操作先做只读检查并明确影响范围。

## 设计约束

- 一个事实只能有一个权威 owner；缓存、projection 和 display 必须能追溯到它。
- 不添加兼容 shim、重复 API、双状态机、第二套配置或临时旁路。
- 不用大范围重构掩盖尚未理解的问题，也不为局部问题修改无关模块。
- 抽象必须减少重复职责或稳定边界；没有复用/所有权收益时保留直接实现。
- 错误应保留作出判断所需的原始上游事实，同时在日志和响应边界脱敏 secret。
- 不把可恢复观测升级成业务权威，也不让遥测失败改写已经确定的业务结果。
- 并发和重试必须先定义幂等键、发送边界、commit 边界和结果不确定语义。
- 测试遵守生产目录边界；不为测试把 mock、fixture 或开关塞进生产源码。

## 参考项目

采用外部实现前同时证明：

1. 当前项目确实缺少该行为；
2. 当前架构存在匹配 owner；
3. 参考行为与当前上游/版本仍一致；
4. 引入后不会复制已有链路；
5. 用户授权范围包含这项实现。

参考代码用于验证机制和请求画像，不用于替代当前项目证据。若参考项目与当前源码冲突，先解释差异，
不要静默移植。

## 验证与收尾

验证目标是证明改动的合同，而不是堆命令。优先运行最窄相关测试，再按风险扩展到 package、workspace、
frontend build 或部署配置；用户明确要求不运行验证时，只做必要的只读 diff/一致性复核并如实说明。

最终交付只报告：

- 已改变的行为和 owner；
- 能证明结果的验证；
- 明确未做、未验证或仍受外部状态阻塞的事项。

不要把排查时间线、空洞原则、未证实猜测或工具输出堆成结论。
