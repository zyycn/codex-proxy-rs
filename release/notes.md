# v3.38.2

## 请求稳定性

- 修复上游返回长 `Retry-After` 时在原账号空等的问题；新增“上游重试等待上限”，默认 240 秒，超限后按原有重试规则尝试换号，无可用账号时返回上游错误并保留原始等待提示
- 在“系统设置 → 运行设置 → 并发与重试”中调整等待上限，统一作用于瞬态重试、WebSocket 传输重试和转 HTTP 回退；该值限制单次建议等待，不是请求总时长
- 修复 Codex OAuth 复用未初始化搜索的 WebSocket 连接后首次启用搜索被拒绝的问题：发送前重建不兼容连接，保留搜索参数与完整输入；依赖原连接的增量请求由客户端按既有机制完整重放
- 收紧账号模型冷却的识别条件，按结构化 `model_not_found` 错误码及状态判断，避免普通参数错误或仅在提示中提及模型不支持时误触发冷却与换号
- 修复代理编辑因版本冲突失败后，紧接着导入账号可能误报代理被占用的问题

## 互联与界面

- 修复 CPR 互联账号池套餐分布遗漏：账号缺少明确套餐时，从已保存的额度快照补全，无需同时开启额度公开；未知套餐仍保持未知
- 修正账号列表 CPR 徽标的图文对齐，更新前后端依赖及构建基础镜像

## 升级事项

- 新增数据库迁移 `0037_retry_after_wait_limit.sql`，服务启动时自动执行，为已有设置填入默认 240 秒
- 等待上限设为 `0` 时不接受正数 `Retry-After`；未提供有效等待建议时仍采用原有本地退避，换号继续遵守次数、续接绑定及安全重放条件
