# v3.40.0

## 升级事项

- **使用 CPR 互联的部署需协调升级两端。** 新版只接受 CPR Link v3 快照。上游和下游均升级后，在下游刷新互联账号以重新识别。第三方互联实现也需适配 `schema_version: 3`。[CPR 互联协议](https://github.com/zyycn/codex-proxy-rs/blob/v3.40.0/docs/api.md#cpr-互联只读协议)
- 从 v3.39.1 升级会执行数据库迁移 `0038`。此后删除 Client Key 会保留其费用明细和预算窗口，删除前已准入的请求仍按原 Key 结算，同名新 Key 单独记账。升级前随 Key 删除的账本无法恢复

## 互联与账号管理

- 互联账号可查看上游密钥的并发和每分钟请求上限（RPM）。账号并发留空时，调度优先采用有效快照中的正数并发上限，其次使用本机默认值。RPM 由上游执行
- 已识别的互联账号同步失败后会显示原因，可通过刷新额度重试。调整了上游账号池、套餐和额度的展示，区分不限额与观测过期
- 账号模型白名单新增手动清理，可选择移除当前目录未返回的模型，保存后生效。刷新目录会保留已选模型。OAuth 授权结果改为通知提示
- 修复恢复探测失败却提前解冻账号的问题。xAI 账号刷新凭据或延后重试时保留已有额度快照，缺少上游额度时可查看过去 24 小时的本地用量

## Chat Completions 与 Responses

- Chat 支持具名工具结果、带文件名的内嵌 PDF，以及通过 `web_search_options` 请求联网搜索。普通搜索响应返回结构化 URL 引用，流式响应保留正文链接。搜索与函数工具需分开请求
- Chat 输出长度上限和 Responses 的 `max_output_tokens` 会传递给 OpenAI 上游，由模型校验并执行
- 大请求因帧大小转为 HTTP/SSE 且需要完整重放时，网关在成功响应后正常关闭空闲 WebSocket，客户端可在新连接上直接发送完整历史。已排队请求仍按序处理，启用 WebSocket 帧中间件时保留连接
- Responses 明确切换上游账号时，清理客户端追踪头、`x-openai-fedramp` 及其元数据副本。同账号请求保留原值

## 用量、插件与运维

- 插件 SDK 支持按固定快照分批扫描历史请求，并按模型、Key、Key 与模型组合或历史路由分组读取完整统计。模型目录优先采用当前账号范围内适配器声明的模型画像，同时保留上游原生 Codex 模型对象
- 请求记录可查看 WebSocket 关闭码、续接失败原因与后续恢复状态，详情可查看已记录的上游错误。修复 PostgreSQL 16 上的用量查询兼容问题
- 新增 `GET /readyz` 供负载均衡器或服务发现判断是否接入流量。升级后先确认返回 204，再切换流量探针。继续用 `/healthz` 监控日志和关键后台任务。镜像和 Compose 默认仍检查 `/healthz`
- 修复 Docker Desktop 上解压只读官方插件文件可能导致在线更新失败的问题。主题编辑器先显示预览画布，再加载预览内容
