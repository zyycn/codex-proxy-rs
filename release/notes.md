# v3.19.0

## 功能改进

- 新增统一部署时区：管理端与 Key 用量页的时间展示、自然日筛选、额度窗口、账号预热、备份计划和日志轮转均遵循 `host.timezone`，默认 `Asia/Shanghai`
- 在设置页「并发策略」中新增「自动审批预留并发」，为 Codex Guardian 请求保留账号名额；开启后，自动审批请求在账号队列中优先等待，设置保存后对新请求生效，默认关闭
- 合并并发控制与排队设置为「并发策略」，并将「调度策略」移到设置页顶部
- 在账号额度重置弹窗中展示 Codex 点数余额，区分无限、零余额和上游未提供余额，并保留小数精度；点数与主动重置卡分别展示

## 问题修复

- 账号预热通过运行设置中的持久化执行游标去重，避免重启或时钟回拨后重复执行已消费的时段；夏令时缺失时刻跳过，重复时刻只执行较早一次
- 修复关闭弹窗时内容提前清空或切换导致的闪动，关闭动画期间保持原有内容

## 升级说明

- 从 `v3.18.3` 升级时自动执行新增的 `0021_runtime_scheduling.sql`，在现有运行设置表中增加预热游标和自动审批预留并发字段；已发布迁移保持不变，升级前请备份数据库
- 可在 `deploy/config.yaml` 的 `host.timezone` 设置 IANA 时区，修改后重启生效；切换时区保留已开启额度窗口的边界与用量，备份计划从当前时刻重新计算后续任务
- 备份计划统一使用部署时区，管理 API 不再使用独立的 `scheduleTimezone` 字段；自定义管理 API 客户端更新运行设置时须包含 `openaiGuardianReservedConcurrency`，填写 `0` 可保持默认关闭状态
